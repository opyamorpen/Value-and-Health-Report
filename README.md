# ONES 客户价值与应用健康度插件

## 总体方案

构建一个部署在客户私有环境中的 ONES Open Platform 2.0 Hosted App，验收基线为私有部署 `v7.22.0`。应用仅在客户环境内读取和计算数据，不向外传输明细。

CSM 进入当前团队的"客户价值与健康度"工作台，选择周期后按需生成不可变报告快照。默认统计近 90 天，并与前 90 天比较。报告包含：

- **客户价值报告**：说明客户已经通过 ONES 完成了哪些工作、形成了哪些协作与交付成果。
- **应用健康度报告**：判断已购能力处于未配置、已配置、有使用或形成闭环哪个阶段。
- **增购机会**：未购模块不计入健康度，根据现有业务证据单独生成机会建议。
- **客户版 PDF**：CSM 核验并编辑规则生成的摘要后，预览、确认并导出。

## 指标与规则

### 客户价值报告

采用团队级聚合，不做个人排名或"人效"评价：

- 项目：新建项目数、活跃项目数、项目状态分布。
- Sprint：新建数、进入终态数、按期完成数、连续迭代趋势。
- Issue：创建数、首次进入完成状态数、重开数、吞吐量趋势。
- 交付周期：从创建到首次完成的 P50/P75 周期；样本不足时显示未知。
- 协作：人工状态/字段变更、评论、工时登记、参与人数的周趋势；过滤系统和自动化账号。
- 计划兑现：仅对有截止日期的工作项计算按期完成率，并显示样本量。
- 知识、测试、DevOps、工时、自动化、Desk、Assistant 等模块按已验证数据补充专属成果。
- 每条价值结论保存指标、周期、查询条件、采集时间、覆盖率和证据引用。
- 不计算未经客户确认的节省金额，不把使用次数直接宣称为 ROI。

### 应用健康度

全产品矩阵按能力维度展示，不生成单一总分：

- Project 与工作项流程
- Sprint、看板与敏捷执行
- Wiki 与知识协作
- Test 与质量闭环
- 代码仓、合并请求与流水线集成
- 工时、资源与排期
- 项目集与 Performance
- 流程自动化
- Desk 服务管理
- Account、SSO、目录与 IM 集成
- Assistant、MCP 与 AI 能力
- 其他已购应用和版本特有能力

统一成熟度为：

1. `未配置`
2. `已配置未活跃`
3. `活跃使用`
4. `形成闭环`

另设 `未购买`、`不适用`、`无法核验`，三者不参与成熟度判断。每个维度展示证据覆盖率、最后采集时间、判断规则和建议动作。

例如代码集成检测：

- 已购买且没有任何仓库配置：`未配置`
- 已配置仓库但 90 天无关联提交/MR：`已配置未活跃`
- 有持续关联提交或 MR：`活跃使用`
- 工作项、代码评审、构建或发布形成可追溯链：`形成闭环`
- 接口失败或版本不匹配：`无法核验`，不能判定为未配置

## 技术实现

- 使用 `ones create` 创建 `ones-node-22` Hosted App，采用 NestJS 后端、React/Vite 前端和 `appSettingPages` 工作台入口。
- 前端通过 `ONES.fetchApp()` 调用后端；后端以 App Identity 获取 OpenAPI Token，所有请求同时满足 OAuth Scope 与 ONES 业务权限。
- 公共 OpenAPI 采集项目、Sprint、Issue、变更日志、评论、工时、Wiki、测试用例库、授权和 ONESQL 数据，严格处理分页、限流、10,000 条变更截断和权限错误。
- 为 v7.22.0 内部接口建立隔离的 `CapabilityDetector` 适配层。先通过目标实例网络请求和页面行为确认代码集成、流水线、自动化、Desk、Assistant、Performance 等合同，再实现探测器。
- 每个内部探测器声明版本、依赖权限、响应校验和降级规则；接口漂移时返回 `无法核验`，不得静默推断。
- 生成任务异步执行，支持进度、失败原因、局部成功和重试；同一团队、周期、规则版本避免重复快照。
- Hosted Entity Storage 保存安装信息、权限配置、规则版本、任务状态、报告快照、人工补证和审计记录；只保存聚合结果及必要证据引用，不长期复制全部业务明细。
- Object Storage 保存 PDF。默认保留报告 24 个月，支持主动删除，卸载时清理插件自有数据。
- PDF 使用确定性服务端模板生成，包含价值亮点、趋势图、健康成熟度、建议路线图和口径说明。CSM 只能编辑叙事与选择导出板块，不能篡改已计算指标。
- 客户版 PDF 默认隐藏内部接口错误、内部销售备注和人员明细；增购建议必须由 CSM 在预览页显式确认。

### 应用接口与核心类型

- `POST /api/report-jobs`：按当前团队、日期范围和规则版本创建任务。
- `GET /api/report-jobs/{id}`：查询阶段、进度、覆盖率和错误。
- `GET /api/reports/{id}`：读取不可变指标快照与可编辑叙事。
- `PATCH /api/reports/{id}/narrative`：保存 CSM 编辑及审计信息。
- `POST /api/reports/{id}/exports`：按确认的板块生成 PDF。
- `GET /api/reports/{id}/evidence`：查看指标口径和证据引用。

核心模型包括 `ReportSnapshot`、`MetricResult`、`CapabilityAssessment`、`EvidenceRef`、`DetectorResult`、`Opportunity` 和 `ExportRevision`。所有结果都携带 `status`、`source`、`collectedAt`、`coverage`、`confidence` 与 `ruleVersion`。

## 权限与安全

- 团队负责人或组织管理员配置报告管理员白名单；只有白名单中的 CSM/管理员可以生成、编辑和导出。
- 后端从已验证的安装及用户上下文取得身份，不信任客户端传入的用户或团队标识。
- App Identity 获取的广泛数据不得通过普通页面接口泄露给未授权成员。
- 记录生成、人工补证、文案修改、导出和删除审计日志。
- 不记录 Token、`shared_secret`、Cookie 或内部接口凭证；安装密钥更新时原子轮换。
- 页面和 PDF 均不提供个人贡献排行榜。

## 实施与验收

1. 在目标 v7.22.0 测试实例完成公共 OpenAPI、内部接口、扩展入口和权限证据矩阵；未验证探测器不得进入实现。
2. 先交付 Project/Sprint/Issue/协作的完整纵向切片，包括快照、工作台、编辑和 PDF。
3. 按全产品矩阵逐项加入版本化探测器、成熟度规则和增购建议。
4. 使用固定数据验证跨周期统计、首次完成、重开、终态 Sprint、机器人过滤、时区边界、缺失值和样本不足。
5. 测试分页、限流、401、Scope 403、业务权限 403、内部接口漂移、部分失败、重复任务及变更日志截断。
6. 在两个实际测试团队验收：一个未配置代码仓，一个已配置且存在关联提交/MR，确认不会把接口不可用误报为未配置。
7. 验证未购模块不降低健康成熟度，只进入独立增购机会。
8. 完成权限越权测试、客户数据不出域检查、PDF 内容脱敏和删除/卸载清理测试。
9. 运行单元、集成、PDF 视觉回归和构建测试；执行 `ones build` 生成版本化 `.opkx`。
10. 分别验证安装、启用、生命周期/JWT、OpenAPI、内部探测器、存储、页面刷新持久化、PDF 下载和生产日志；使用登录态浏览器完成真实 ONES 页面验收。

## 已定假设

- 首版仅分析当前单个团队，不做组织级跨团队聚合。
- 首版按需生成并保存快照，不包含月度调度或自动发送。
- 叙事由可追溯规则模板生成，CSM 人工确认，不接入 LLM。
- 内部接口按 v7.22.0 锁定；"全自动"是探测目标，不取消 `无法核验` 的安全降级。
- 正式实施需要一个可调试的 v7.22.0 环境、相应管理员权限，以及分别具备/不具备代码集成的验收样本。
